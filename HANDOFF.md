Цей файл — знімок стану проекту на момент завершення поточної сесії. Прочитай його

## Що це за проект
Односторінковий сайт-калькулятор для перекупів авто (GTA RP сервер Radmir).
Персональні кабінети через Firebase Auth, історія угод в Firestore.
Хостинг — GitHub Pages, автодеплой при push у `master`.

- Репо: https://github.com/nemesio-shks/reseller-calculator
- Сайт: https://nemesio-shks.github.io/reseller-calculator/

## КРИТИЧНО ВАЖЛИВІ НЮАНСИ (не проґав це!)

### 1. Ліміт результатів пошуку колись був занизький
Був баг: показувалось тільки 15 перших збігів, і популярні моделі (напр. "Toyota LC 300") не
влазили в список коли збігів було >15 (напр. "Toyota" дає 18 збігів). **Виправлено**: ліміт
підняли до 40 + додали сортування за релевантністю/класом/ціною. Якщо знову скаржаться що
щось "не знаходиться" — перевір скільки всього збігів на цей запит і чи не вилазить за ліміт 40.

### 2. "Загальні витрати" — розрахунок навпаки інтуїції
`totalCost = car.buyPrice - adjTotal`. Тобто якщо `adjustments` містить `{desc: "тюнінг", amount: -300000}`
(тобто витрата, від'ємне число), то `totalCost = buyPrice - (-300000) = buyPrice + 300000`.
Це навмисно, користувач просив саме так: "мінус в правках" = "витратив ще грошей" = загальні
витрати мають ЗРОСТИ, а не впасти. НЕ міняй цю формулу назад на `+adjTotal`, це вже виправлений баг.

### 3. Кастомне відео/GIF фону — НЕ синхронізується між пристроями
Зберігається через IndexedDB (`reseller_calc_media` / store `bgMedia`, ключ `'bgCustomFile'`) —
це локальне сховище браузера, не Firestore. Причина: відео важить мегабайти, а Firestore документ
обмежений 1MB. У `state.bgType` є значення `'custom-video'`, а сам блоб лежить окремо. При
завантаженні сторінки на іншому пристрої/браузері `bgType` збережеться як 'custom-video', але
файлу там не буде — код в `applyBackground()` обробляє `!stored` (просто нічого не покаже).
Якщо колись знадобиться синхронізація — треба Firebase Storage (не Firestore), окреме налаштування.

### 4. Іконка авто в історії — це `<div>` з background-image, не `<img>`
Через застосування `iconPos` (позиція/зум з редактора) для маленької мініатюри використовується
наближена конвертація пікселів offset → % через `carIconBgPosition()` — це ГРУБЕ наближення
(ділення на 3, кліп ±40%), не точна відповідність тому що бачиш в редакторі. Це свідомий
компроміс заради простоти, працює прийнятно візуально.

### 5. Довідник авто (`assets/cars/cars.json`) — не редагуй вручну без потреби
Генерується скриптом `parse_cars.js` (парсить HTML з `Library CARS/`, обидва в `.gitignore` —
НЕ в git, тільки локально) → потім `compress_cars.js` стискає фото через ffmpeg і кладе в
`assets/cars/` (це вже деплоїться). Якщо користувач додасть ще сторінки вікі в `Library CARS/`,
треба:
```bash
# 1. Додати новий файл у масив `files` в parse_cars.js (з правильною категорією/label)
# 2. Перезапустити обидва скрипти:
rm -rf CarsDatabase assets/cars
node parse_cars.js
node compress_cars.js
# 3. Перевірити git status — мають з'явитись нові assets/cars/**, змінений cars.json
git add assets/cars/
git commit -m "..."
git push
```
Категорії зараз: econom, middle, premium, trucks, moto, water, air, rare, exclusive, rv.
Порядок "клас від малого до великого" визначений в `cars-data.js` → `window.CAR_CATEGORY_ORDER`.

(як зроблено в `compress_cars.js` через `execFileSync(FFMPEG, [...])`).

### 7. Firebase — реальні ключі вже налаштовані і працюють
`firebase-config.js` містить справжній конфіг проекту `reseller-calculator-b7217`. Auth
(email/password) і Firestore вже увімкнені і з правилами безпеки (кожен юзер бачить лише
свій документ `users/{own-uid}`). Ліміти Spark plan з запасом вистачає для цього проекту.

### 8. Пошук: 40 результатів + ієрархічне сортування, НЕ повертай ліміт 15 назад
Логіка в `renderCarSuggestions()` (script.js): фільтр за назвою (з транслітерацією/аліасами) →
сортування за `window.CAR_CATEGORY_ORDER` індексом категорії → за ціною (`parsePrice()` парсить
рядок типу "1.800.000" в число) → за алфавітом → `.slice(0, 40)`. Якщо колись знову скаржаться
що щось не показується в пошуку — спочатку порахуй скільки всього збігів на запит, це майже
завжди причина (не баг фільтрації, а обрізання списку).

### 9. Експорт/імпорт пресету — формат файлу = один `project` об'єкт, НЕ весь `state`
Файл `{назва}_preset.json` містить одне вкладення `project` (id/name/currency/cars), НЕ весь
`state` (без theme/bgImage/projects-масиву). Імпорт створює НОВИЙ `id` через `uid()` для проекту
і для кожного авто всередині (щоб не було колізій id з існуючими проектами користувача).
Валідація мінімальна: перевіряється лише що `imported.cars` є масивом. Якщо треба зробити
експорт/імпорт усього акаунта (всіх проектів + налаштувань) — це інша фіча, поки не робили.

## Файлова структура (доповнення до TECH_NOTES.md)
```
cars-data.js         — завантажує assets/cars/cars.json через fetch(), формує window.CARS_FLAT_LIST
                       (плаский масив усіх авто для пошуку) і window.CAR_CATEGORY_ICONS/ORDER
parse_cars.js        — ЛОКАЛЬНИЙ скрипт (не в git), парсить HTML з Library CARS/ → CarsDatabase/
compress_cars.js     — ЛОКАЛЬНИЙ скрипт (не в git), стискає фото з CarsDatabase/ → assets/cars/
Library CARS/        — ЛОКАЛЬНО (не в git), збережені вручну HTML-сторінки вікі Radmir
CarsDatabase/         — ЛОКАЛЬНО (не в git), сирі непристиснуті фото + cars.json (~76-90MB)
assets/cars/          — ДЕПЛОЇТЬСЯ, стиснуті фото (~13MB) + cars.json (фінальна версія для сайту)
assets/bg-video.mp4   — дефолтне відео фону (~12.8MB, прозоре, стиснуте)
HANDOFF.md            — цей файл
TECH_NOTES.md         — базові технічні нотатки (архітектура, модель даних, деплой)
```
